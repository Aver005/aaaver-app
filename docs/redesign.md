# Редизайн 2026-09: журнал

Один заход: фундамент + три ветки с разными вариантами дизайна. Здесь —
цель, находки, план после аудита, решения, отложенное и прогресс.

## Цель

Сайт последний раз верстался в июне–июле 2026. Задача — кардинально
улучшить визуал и подачу, отразив автора как разработчика: что он строит,
как думает, какой у него почерк. Без перегибов: дорого выглядят Linear,
Raycast, Vercel — не «неон и градиенты».

## Кто автор (по его проектам, не по резюме)

- Строит себе инструменты вместо чужих: TUI-агент на Rust (PoopRusteek),
  его TS-предшественник (PoopSeek), image-движок craws с MCP-сервером,
  пакетный менеджер ins, CLI без зависимостей (glw).
- Любит границы и документацию как жанр: `.memories/`, ADR, ARCHITECTURE
  «про решения и их цену», сервер на `Bun.serve` без фреймворка, ноль
  зависимостей там, где можно.
- Схема «тяжёлый счёт дома, лёгкий сервер на VDS»: diary (голосовой
  дневник), tg-multi-tool (воркер за NAT приходит сам).
- Музыка сквозной темой: RapSync, curlynator, rap-analytics, Maushi.
- Голос: скатологический нейминг снаружи, литературные коммиты внутри.
- Визуальный принцип из его же CLAUDE.md: **«страница = сам продукт»**.
  Тёмная база с температурным сдвигом (никогда чистый чёрный), костяной
  текст, один акцент, зерно, моно-кикеры капсом, нумерация секций,
  огромный дисплейный шрифт, нижний статус-бар как у TUI, живая демка
  вместо скриншота. JetBrains Mono — в шести проектах подряд.
  Никогда: Inter/Roboto как дисплейный, градиентные кнопки, стоковые
  иллюстрации, скругления больше 8–10px, «мягкий SaaS».

## Исходная точка: находки

Что уже хорошо: редакционная структура, ember-акцент, slide-to-send с
proof-of-work, FSD, сервер без зависимостей, хостинг демок внутри сайта.

Баги и устаревшее (починено в фундаменте):

1. Футер обещал SQLite — база давно Postgres.
2. Подсказка «подтвердите согласие» не пряталась после галочки: класс
   `opacity-100` был захардкожен, менялся только `aria-hidden`.
3. Карточка Pocacall вела на домен, который не отвечает.
4. Снимок репозиториев для фолбэка устарел и собирался без фильтра —
   в него (и в ленту прода) попадали служебные репозитории.
5. «55+ публичных репозиториев» и «10+ в продакшене» — числа, которые
   нельзя проверить и которые протухают; убраны.
6. Блокировка прокрутки под меню и под модалкой дублировалась в двух
   местах и затирала друг друга.
7. Полиморфные корни карточек через `as 'a'` — обход типов.
8. Локальный `.env` содержал переменную из эпохи SQLite.
9. Секции появляются по `whileInView`: полностраничный скриншот без
   прокрутки — чёрный. Для людей не баг, для проверок — помнить.

Аудит плана тремя независимыми ревьюерами (архитектура, дизайн,
продукт/риски) добавил маркеры «сгенерированного портфолио», которые
убраны: контурная фамилия, призрачные номера за заголовками, плитки
«7+ / 55+», капсулы тегов, «&» в кружке, звёзды при значении меньше
десяти, пульсирующая точка, свечение за курсором и точечная сетка
(зерно или сетка — что-то одно).

## Дев-окружение

- `docker-compose.dev.yml` — Postgres 17 на `127.0.0.1:5433`, том отдельный.
- `.env.local` (не в git, Bun читает поверх `.env`): `DATABASE_URL` на
  локальную базу и **пустой `TELEGRAM_BOT_TOKEN`** — сообщения с формы в
  деве копятся в базе и не улетают в живой Telegram.
- `sites/<slug>/` — локальные сборки демок (каталог в `.gitignore`):
  окно демки проверяется на настоящих `dist`, а не на заглушках.
- Прод не трогаем: пуш в `master` = автодеплой, поэтому ветки только
  локальные, пушит и мержит автор. На время работы push-адрес `origin`
  можно отключить: `git remote set-url --push origin DISABLED` (вернуть —
  тем же способом с настоящим адресом). Сейчас адрес настоящий.

## Фундамент — ветка `redesign/base`

Общая часть для всех вариантов. Дизайна почти не касается: базовый UI
нарочно простой, каждый вариант переписывает `ui/` по-своему.

### Модель проекта

`entities/project/model/types.ts`: вид (`product | tool | game`), статус
(`active | paused | archived` — «живая демка» не статус, а факт рантайма
из `/api/sites`), период, роль, `summary`, стек, факты `{ value, label }`,
ссылки `site`/`repo` раздельно, `images` (первый — обложка, два и больше —
галерея). Витрина — `ShowcaseEntry`: `single` или `pair` (PoopSeek →
PoopRusteek), нумерацию считает `numberShowcase`, а не JSX. Действие
карточки — `ProjectAction`: демка внутри сайта, сайт или репозиторий.
Подписи видов и статусов — `Record<Locale, …>`: новый вид без перевода
не соберётся.

Карточки переехали из `entities/project/ui` в `widgets/projects/ui`:
потребитель один, а виджет может легально импортировать фичу окна демки.

### Правило чисел

На сайте только то, что либо считается при рендере из API (звёзды,
даты пушей), либо структурно стабильно и проверяемо чтением кода
(«8 провайдеров», «0 зависимостей», «MCP + ACP»). Растущие счётчики
(коммиты, тесты) и приватные репозитории — без чисел.

### Окно демки

`features/demo-window`: модульный стор на `useSyncExternalStore` (без
провайдера — открыть окно может любой виджет), `DemoLink` (обычная
ссылка на `/<slug>/`, с курсором на широком экране перехватывает клик),
хост `DemoWindow` на странице. Только для слагов из `/api/sites` — иначе
SPA-фолбэк показал бы сайт внутри сайта.

- `sandbox` без `allow-top-navigation`: демка не может увести с сайта.
  `allow-same-origin` оставлен намеренно: демки — собственный код автора
  и уже раздаются с того же origin, окно не добавляет доступа, которого
  нет у обычной вкладки `/craws/`.
- Открытие кладёт запись в историю: «назад» закрывает окно, а не уводит
  с сайта. Роутер демки пишет в ту же историю — тогда «назад» сначала
  листает демку.
- Esc внутри iframe до родителя не доходит — кнопка закрытия обязательна.
- Все модалки (согласие, демка) — на одном `shared/ui/Overlay`: портал в
  body, `inert` на приложении, блокировка прокрутки, возврат фокуса.

### Общее

- `shared/config/sections.ts` — единый реестр разделов (порядок, якоря,
  номера) для навигации, рейки, оглавления.
- Хуки: `useScrollLock` (счётчик вложенных блокировок), `useEscapeKey`,
  `useActiveSection`; `relativeTime` на `Intl.RelativeTimeFormat`, не
  мельче суток — данные кэшируются на шесть часов, точнее нечестно.
- `useRepos` — один запрос на страницу, разделяется hero, лентой и
  статус-баром; отдаёт `live`, чтобы подписать «снимок от даты».
- Сервер: фильтр репозиториев вынесен в `server/lib/github.ts` и
  используется и роутом, и `scripts/repos-snapshot.ts`; кэш ответа
  дублируется в памяти процесса — лежащая база не роняет ленту в снимок,
  пока GitHub жив; `GITHUB_TOKEN`, если задан, поднимает лимит API.
- `html { scrollbar-gutter: stable }` — модалки не дёргают макет.

### Структура страницы

hero → проекты → опыт → open source → контакт. Секции «Обо мне» и «Стек»
убраны: три строки о себе живут в спецификации hero, стек — в каждой
пластине. Проекты в два яруса: пластина там, где есть живая демка или
проверяемые факты, строка — всё остальное. В опыт добавлена строка Maushi
(фриланс с 2025) — это три года реальной работы.

## Варианты (после аудита)

### A — `redesign/workbench` («верстак»)

Тёмный тёплый уголь, костяной текст, ember. Рейка разделов слева
**вместо** верхнего меню на десктопе (не третья навигация), без полосы
прогресса; статус-бар 28px — только живые данные; hero — контраст толщин
Unbounded (проверить кириллицу на тонком начертании поверх зерна);
пластины на 12-колоночной сетке без рамок-карточек; первая пластина
работает сама при появлении. Запоминается: демки открываются внутри сайта,
факты вместо прилагательных.

### B — `redesign/terminal` («терминал»)

Не окно с кружочками, а типографическая система на символьной сетке
(`ch` × `lh`); фирменная палитра ember по умолчанию, пресеты `midnight`
(из PoopRusteek) и `paper` — как демонстрация движка тем; одна командная
строка в статус-баре, как `:` в vim, с кликабельными подсказками —
команды `help`, `ls`, `open <slug>`, `cat <раздел>`, `lang`, `theme`;
контакт = промпт, ползунок — его Enter. Без псевдографики и сканлайнов.

### C — `redesign/paper` («бумага»)

Светлый: бумага `#EDEAE3`, чернила `#1A1916`, акцент `#B8401A` для
крупного и `#9E3413` для мелкого моно (AA). Без зерна, меток обрезки и
фолио. Маргиналии на полях в моно — «почему так» рядом с пластинами,
как ADR; колофон; графитовые полосы на всю ширину под окна демок и форму.

### Приёмка варианта

1. `bun run typecheck`, `bun run build`; бюджет: JS ≤ 150 KB gz,
   CSS ≤ 25 KB, ноль новых семейств шрифтов.
2. Reduced motion: секции видны без прокрутки, бегущие строки выключены.
3. Клавиатура: Tab по навигации, карточкам, окну демки (открыть,
   закрыть, фокус вернулся), ползунку отправки.
4. RU/EN на 1440 и 390 px: длинные слова в дисплейном шрифте не
   переполняют, статус-бар не режется.
5. Снимок репозиториев перегенерирован фильтром; в данных нет
   непроверяемых чисел.

## Решения

- Шрифты остаются те же три семейства (Unbounded, Golos Text,
  JetBrains Mono): новые пакеты — новые зависимости, а вариативные оси
  дают достаточный диапазон (Unbounded 200–900). Желаемые альтернативы
  для варианта C — Fraunces и Spectral — записаны, не подключены.
- Внешние сайты (Maushi, OtaScribe) окном не открываются: чужие заголовки
  могут запретить iframe, и ломать чужие сайты незачем.
- Пресетов тем в варианте B три, а не восемь: каждый — отдельное
  непроверенное состояние.

## Отложено / вопросы к автору

- WarCube: публичная репа — ранняя версия 2025 года, а описание — про
  текущий приватный код. В тексте это сказано прямо; открыть репу или
  убрать ссылку — решение автора.
- Pocacall: домен не отвечает — переведён в «архив» без ссылки.
- Для несмонтированного слага сервер отдаёт SPA-фолбэк, а не 404; окно
  демки это не задевает (открывается только по `/api/sites`), но для
  чистоты сервер мог бы отвечать 404 на неизвестные пути.
- Строка Maushi в опыте — добавлена как фриланс; если так не хочется
  показывать, убрать одну запись в `entities/experience/model/data.ts`.
