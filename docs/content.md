# Где менять контент

Базы данных для контента нет — всё лежит в коде, меняется правкой файла
и пересборкой (`docker compose up --build -d`).

## Тексты интерфейса (RU/EN)

`src/shared/i18n/dict.ts` — единый словарь: hero (кикер, лид, био,
спецификация), заголовки секций, форма, футер, окно демки, статус-бар.
Два объекта, `ru` и `en`, структура у них одинаковая, TypeScript не даст
забыть перевод.

## Проекты

`src/entities/project/model/data.ts`. Два яруса: `SHOWCASE` — пластины
(есть живая демка, скриншот или проверяемые факты), `TOOLS` — компактные
строки. У проекта есть:

```ts
{
    id: 'craws',                    // = слаг демки в sites/, если она есть
    title: 'craws',
    kind: 'tool',                   // product | tool | game
    status: 'active',               // active | paused | archived
    period: { from: '2026-07' },    // 'YYYY' или 'YYYY-MM'; без to — по сей день
    role: { ru: '…', en: '…' },
    summary: { ru: '…', en: '…' },  // два-три предложения
    stack: ['Rust', 'MCP'],
    facts: [{ value: '34', label: { ru: '…', en: '…' } }],
    links: { site: 'https://…', repo: 'https://github.com/…' },
    images: ['/projects/craws.webp'],   // первый — обложка, два и больше — галерея
}
```

Пара «братьев» (PoopSeek → PoopRusteek) — запись `{ type: 'pair', label,
projects: [a, b] }` в `SHOWCASE`; нумерация считается сама.

Правило чисел: в `facts` только то, что проверяется чтением кода и не
растёт само («8 провайдеров», «0 зависимостей»). Коммиты, тесты и звёзды
руками не пишем — звёзды и даты пушей приходят живыми из GitHub.

Живая демка — не поле данных, а факт рантайма: если в `sites/<id>/` лежит
собранная демка, карточка сама получает «Открыть демку». Внешние сайты
окном не открываются, только новой вкладкой.

Скриншоты лежат в `public/projects/`, пропорция — 16:10, оптимальная
ширина ~1200px, формат webp. У проекта без скриншота (бот, сервис без
экрана) можно нарисовать схему: `widgets/projects/ui/figures/`, реестр по
`id` в `figures/index.ts`.

## Опыт работы

`src/entities/experience/model/data.ts`. Поле `to: null` означает
«по настоящее время». Порядок в массиве = порядок на странице
(сверху — свежее).

## Стек

Отдельной секции нет: стек каждого проекта — в его `stack`. Список
`src/entities/skill/model/data.ts` остаётся для бегущей строки, если
вариант дизайна её использует.

## Open Source

Секция сама тянет репозитории с GitHub (см. `server/lib/github.ts`):
не форки, не архив, отсортированы по последнему пушу. Спрятать
репозиторий — добавить имя в `HIDDEN` там же. Если у репозитория нет
описания на GitHub, но он есть в `data.ts` со ссылкой `links.repo`,
подставится `summary` проекта.

Снимок для фолбэка (`src/entities/repo/model/fallback.ts`) обновляется
скриптом `bun scripts/repos-snapshot.ts` — руками не править.

## Контакты и ссылки

`src/shared/config/site.ts` — телеграм, почта, GitHub, репозиторий сайта,
часовой пояс для статус-бара. Разделы главной и их номера —
`src/shared/config/sections.ts`.

## SEO-мелочи

`index.html` — title, description, OG-теги, JSON-LD. Фавиконки в
`public/`.
